# NSeqArpKeys release roadmap

Updated 2026-09-24. Version 1.2.0 ships the pattern timing, rhythm and editing
features already implemented on this branch, with the reliability work below.
The remaining milestones are future releases; they are not prerequisites for 1.2.0.

## Version 1.2.0 - timing, expression and independent pattern editing

The release is a playable per-key pattern instrument. Each MIDI key owns an
independent assignment. Whole presets remain self-contained performance setups.

### Included features

- [x] Per-key Steps/QN: 0 inherits the existing global parameter; 1-16 overrides it.
  Different keys run at different rates. The editor shows the effective rate.
- [x] Preserve global host parameter IDs and legacy preset timing. Missing per-key
  timing means inheritance. Meter Num remains a saved grouping value and does not
  change playback duration.
- [x] Preserve musical phase and outstanding note-offs when tempo, global subdivision,
  or an active key's subdivision changes. Other assignment edits restart that key
  with its captured trigger velocity.
- [x] Melodic Forte mapping and rhythmic mapping of bits 0-15 to 16 editable MIDI
  notes. Switching modes preserves the selected MIDI output channel.
- [x] Saved Preview sound toggle for silent MIDI output to another instrument.
- [x] Base and trigger velocity, a 0-127 velocity lane (zero mutes), semitone pitch
  offsets, chromatic transpose, rotation and reversal. Both lanes cycle within
  the integer pattern and restart at each loop; rotation/reversal affect only
  integer steps. Independently running lane clocks are deferred.
- [x] Pattern names, copy/paste, duplicate to next key, and bounded editor-session
  undo/redo. Assign range creates independent copies, optionally transposed by
  distance from the source key, with a single undo transaction.
- [x] Single-pattern `.nseqpattern` save/load through a file chooser, alongside the
  existing whole-preset browser and `.nseqpreset` import/export. Loading one
  pattern affects only the selected assignment and is undoable.
- [x] Validate integer input without partially applying malformed text. Bound
  sequences and lanes to 4096 values; preserve empty and all-rest loop lengths.
- [x] Track shared MIDI pitch ownership in chronological order across keys;
  muted steps cannot release another step's notes. Stop/release/retrigger must
  leave no held notes behind.

### Release checks

- [x] Automated regression coverage for note lengths, shared pitches, muted and
  quiet expression, simultaneous rates, live rate/tempo changes, state round trips,
  legacy defaults, pattern file round trips, independent copies and grouped undo.
- [x] Native VST3 build, editor smoke check, tests and release archive
  verification on Windows. Record current results in the implementation status.
- [x] Updated HTML/PDF manual, with visual inspection of the printable output.
- [ ] Run the updated GitHub Actions matrix on Windows, Linux and macOS (including
  AU on macOS), with all three test targets and native packaging.
- [ ] Additional host coverage: smoke-test MIDI routing and project reopen/automation in a
  real VST3 host and AU host on supported systems.

Acceptance: at 120 BPM, subdivision 4 steps every 125 ms while subdivision 3
steps every approximately 166.667 ms. Selecting another key does not alter either
pattern. Changing a rate preserves phase. Duplicating or loading one assignment
leaves the other keys intact. Saved projects reopen with the same musical settings.

## Distribution

Version 1.2.0 ships VST3 on Windows/Linux/macOS and AU on macOS. The standalone
wrapper is removed because MIDI generation depended on an available audio device.
Any future standalone app must use an independent MIDI clock with optional audio preview.

## Future milestone 1 - pattern library and editing workflow

Target: a later release, provisionally 1.3.x. The file-based pattern workflow is
sufficient for 1.2.0; this milestone adds a richer library and shared identity.

- Cut and clear actions; selective paste of all settings, sequence, timing or expression.
- Pattern colours, tags, favourites and auditioning, plus a searchable bank browser.
- Assign bank entries by drag/drop or a keyboard context menu.
- Distinguish independent Duplicate from shared Link; offer Make independent.
- Embed shared pattern definitions and key/range mappings in whole presets so
  exported setups never depend on another machine's local bank.
- Step/bit preview, sounding-key indicators, loop length and richer validation feedback.

Acceptance: edits to a duplicate leave its source intact; linked assignments follow
shared edits. Exported presets reopen with every required pattern on a clean install.

## Future milestone 2 - shared ranges and keyboard expression

- A distinct range model with root key, input-channel filter and output channel.
- Fixed pitch, chromatic and Forte set-degree transposition; explicit pitch-lane units.
- One range-position mapping to transpose, rotation, density, velocity or rate.
- Adjustable trigger-velocity sensitivity/curve, beyond 1.2.0's linear scaling.
- Visible priority for overlapping ranges; optional layering in a later iteration.
- Independent active instances for held keys in a range; releasing one must not stop another.

Example: C3-B3 shares a pattern and transposes it through a Forte set, while another
range plays fixed-pitch rhythm variations. This extends 1.2.0's independent range copies.

## Future milestone 3 - extended rhythm and timing

- Optional velocity-encoding bits per drum lane, with explicit word width and bit order;
  zero means no trigger and nonzero values map to MIDI velocity 1-127.
- Independent accents, hit probability, ratchets and configurable drum gate lengths.
- Density-preserving mutations, seeded for repeatable results.
- Swing, deliberate microtiming and, later, a bounded time-warp function with event preview.

Acceptance: the existing binary lane mapping remains compatible (integer 5 triggers
lanes 0 and 2). Rotation/mutation preserve the requested hit count, and saved seeds
reproduce generated rhythms.

## Future milestone 4 - operators and modulation

- Pure C++ block permutation, repetition, concatenation, interleaving and masks,
  extending the existing rotation and reversal.
- Keep time reversal, pitch inversion and bit reversal distinct in the interface.
- Non-destructive operator chains with preview, bypass, reorder, reset and Bake to new pattern.
- Explicit unequal-length combination policies: cyclic zip, truncate, pad or Cartesian
  product. Show the resulting length before committing.
- Independent velocity, pitch, gate, probability and rotation lanes with their own
  length, rate and phase; advance per step or per sounding event; retrigger or free-run.
- MIDI CC/expression mappings and assignable macros. Bound event generation and keep
  expensive transformations outside the audio callback.

Example: independently cycling 16-step rhythm, 5-step accent and 7-step pitch lanes
realign after 560 steps. This is a future extension to 1.2.0's loop-local lanes.

## Future milestone 5 - performance and evolving composition

- Quantized launches with restart, legato and phase-continuous switching.
- One-shot, hold and per-assignment latch, plus exclusive groups.
- Scenes recalling active assignments and macros, with explicit sustained-note transitions.
- Pattern chains and follow actions: choose successors after N cycles using weights/constraints.
- Seeded mutation with locked steps/lanes and bounded amounts; capture results into the bank.
- Record performed MIDI and export or drag a chosen number of cycles into a DAW.
  Do not assume polymetric combinations have a short common cycle.
- Later exploration: predicate-constrained rhythm completion, ternary event encoding,
  and GateRunner-inspired scene activation masks.

## Architecture for future work

Keep pattern definitions, key/range assignments, active instances and performance
presets distinct when introducing shared identity. Active instances own trigger
identity, phase, captured expression and outstanding notes. Presets embed their
required definitions and mappings. Prepare immutable playback data outside the
audio callback, and keep file access/parsing off that thread. Expand real-time
allocation and locking improvements as the playback model grows.

Borrow rhythm, pitch/velocity and time-transformation semantics from
[GateRunner](https://github.com/ncg777/gaterunner), and bounded pure transformations
from [sequence-operator](https://github.com/ncg777/sequence-operator). Retain the
existing whole-preset browser conventions and versioned compatibility.
