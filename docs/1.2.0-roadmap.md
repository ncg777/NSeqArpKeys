# NSeqArpKeys: a playable pattern instrument

Proposed roadmap — 2026-09-24. Planning and source inspection only; no application changes or runtime reproduction performed.

## Direction

Make reusable patterns playable across a keyboard: each pattern carries its timing and musical behaviour, while key/range assignments determine how a performer triggers and transforms it. Prioritize quick experimentation, syncopation, expressive playing and recall.

## Verified baseline

Inspected the current default-branch sources in ncg777/NSeqArpKeys, plus the GateRunner and sequence-operator READMEs.

- NSeqArpKeys already has per-key sequences, Forte sets, output channels, octaves, Gate and Fixed Steps, simultaneous triggered patterns, latch and stop controls.
- The existing preset browser saves all 128 assignments and supports search, favourites, duplication and import/export. A reusable individual-pattern bank is a separate addition.
- Meter numerator and denominator are global host parameters. KeyAssignment has neither field. Selecting a key loads its sequence and musical settings but cannot recall a per-key denominator.
- PatternScheduler computes one step duration for all active patterns: 60 / (BPM × denominator). The denominator therefore means steps per quarter note under this timing convention, not a conventional time-signature denominator.
- The scheduler receives numerator but does not use it in its step-duration calculation.
- Generated MIDI note-on velocity is hard-coded to 100; input trigger velocity is not propagated to generated events.
- Loading a whole preset explicitly restores the global denominator and updates its slider. All six factory presets currently use denominator 4. The reported behaviour when switching individual keys is explained by the current global model; a failure between saved whole presets with different denominators would require separate reproduction.

## Milestone 0 — Reliable timing and state

- [ ] Add per-pattern subdivision with an explicit “inherit global” option. Show the effective value when selecting a key.
- [ ] Label the control “Steps per quarter” or “Subdivision”; treat bar grouping separately. Preserve existing host parameter identifiers.
- [ ] Store each active instance's effective timing independently. Two keys must run at different subdivisions concurrently.
- [ ] Preserve old project/preset sound and automation by treating missing per-pattern subdivision as global inheritance. Saving and reloading must preserve that relationship.
- [ ] Define live rate-change behaviour: maintain musical phase and ensure outstanding notes receive their correct note-offs. Avoid reinterpreting all past elapsed samples using a new rate.
- [ ] Ensure host automation updates the displayed global control; current editor refresh is tied to state-restore revision.
- [ ] Add regression coverage for selection, edits, duplication, preset import/export, editor reopening, DAW state restore, simultaneous subdivisions, tempo changes and note-offs.

Acceptance example: at 120 BPM, a pattern at subdivision 4 steps every 125 ms, while another at subdivision 3 steps every approximately 166.667 ms. Switching editor selection changes neither pattern's playback. Old presets retain their former timing.

## Milestone 1 — Editing and reusable patterns

- [ ] Copy, cut, paste, duplicate, rename and clear individual patterns; add undo/redo.
- [ ] Offer paste all settings, sequence only, timing only and expression only.
- [ ] Add independent pattern names, colours, tags, favourites and auditioning.
- [ ] Add a pattern bank supporting import/export and assignment by drag/drop or a keyboard context menu.
- [ ] Distinguish Duplicate from Link. Duplicate creates an independent editable pattern; Link shares a pattern definition between assignments. Provide Make independent.
- [ ] Keep whole presets as complete performance setups containing the required pattern definitions and key/range mappings; avoid dependencies on another machine's local bank.
- [ ] Add a step/bit preview, sounding-key indicators, loop length and validation messages alongside integer entry.

Acceptance: duplicate A to B and edit B without changing A. Linked assignments follow shared edits. Exported presets reopen with all required patterns on a clean installation.

## Milestone 2 — Keyboard ranges and expression

- [ ] Assign a pattern to a range with a root key, input channel filter and output channel.
- [ ] Offer fixed pitch, chromatic transposition and transposition by degrees of the chosen Forte set.
- [ ] Allow range position to control a selected parameter: transpose, rotation, density, velocity or rate. Start with one mapping per range.
- [ ] Add trigger-velocity sensitivity, a base velocity, a velocity curve and a per-step velocity lane.
- [ ] Add a pitch-offset lane with explicit semitone or set-degree units; keep pitch offsets distinct from integer bitmask arithmetic.
- [ ] Define overlapping range behaviour explicitly. Start with visible priority; make layering an optional later mode.
- [ ] Support independent instances when multiple keys in one range are held. Releasing one trigger must not stop another.

Example: assign one pattern across C3–B3. Keys transpose it through a Forte set; playing harder increases its accents. A second range plays fixed-pitch rhythmic variations.

## Milestone 3 — Rhythm mode

- [ ] Add an explicit melodic/rhythmic mode rather than overloading the existing integer meaning.
- [ ] In rhythmic mode, map bits to a configurable ordered list of output MIDI notes, independent of the Forte set.
- [ ] Begin with binary lane gates. Add optional multiple bits per lane for velocity, with zero meaning no trigger and nonzero values mapped to 1–127.
- [ ] Default rhythmic output to MIDI channel 10, while keeping channel and drum-note mappings editable.
- [ ] Add independent accent lanes, rests, hit probability, ratchets and configurable drum gate lengths.
- [ ] Add Euclidean generation with pulse count, step count and rotation; add density-preserving mutations for controlled variation.
- [ ] Add swing, deliberate microtiming and later a bounded time-warp function. Preview final event positions.

Acceptance: integer 5 with one bit per lane triggers lanes 0 and 2. Velocity encoding has an explicit word width and bit order. Rotation preserves hit count. Saved random seeds reproduce generated rhythms.

## Milestone 4 — Operators and modulation

- [ ] Port selected sequence-operator semantics into pure C++ transformations: reverse, rotate, block permutation, repetition, concatenation, interleaving and masks.
- [ ] Keep time reversal, pitch inversion and bit reversal distinct in the interface.
- [ ] Add non-destructive operator chains with preview, bypass, reorder, reset and Bake to new pattern.
- [ ] For unequal sequence lengths, require an explicit combination policy, such as cyclic zip, truncate, pad or Cartesian product. Display the resulting length before committing.
- [ ] Add modulation lanes for velocity, pitch, gate, probability and rotation, each with its own length, rate and phase.
- [ ] Choose whether a modulation lane advances per step or per sounding event. Allow retrigger or free-running phase.
- [ ] Add MIDI CC/expression mappings and a few assignable macros. Bound event generation and evaluate expensive transformations outside the audio callback.

Example: a 16-step rhythm, a 5-step accent lane and a 7-step pitch lane realign after 560 steps when advanced together. This creates long development from compact material.

## Milestone 5 — Performance and evolving composition

- [ ] Quantize launches to a chosen grid; offer restart, legato and phase-continuous switching.
- [ ] Add one-shot, hold and per-assignment latch behaviour, plus exclusive groups for replacing related patterns.
- [ ] Add scenes that recall active assignments and macros, with deliberate control over sustained-note transitions.
- [ ] Add a pattern chain and follow actions: after N cycles, choose a successor by explicit weights or constraints.
- [ ] Add seeded mutation with locked steps/lanes and a bounded mutation amount; capture any result into the bank.
- [ ] Record performed MIDI and export or drag a chosen number of cycles into a DAW. Do not assume polymetric combinations have a short common cycle.
- [ ] Later exploration: predicate-constrained rhythm completion, optional ternary event encoding, and scene activation masks inspired by GateRunner.

## Architectural guidance

Separate four concepts:

| Concept | Responsibility |
| --- | --- |
| Pattern definition | Sequence, mode, timing, note interpretation, expression lanes and operator chain |
| Key/range assignment | Pattern reference, trigger range, root, transposition and performance overrides |
| Active instance | Trigger identity, phase, captured expression and outstanding notes |
| Performance preset | Embedded pattern definitions, assignments, globals, scenes and compatibility version |

Keep bank edits, linking and duplication understandable. Store immutable/prepared playback data for the scheduler, and keep file access, parsing and expensive transformations off the audio thread. Define MIDI note ownership across simultaneous instances so one instance's release does not unexpectedly silence another sharing its channel and pitch.

## What to borrow

| Source | Candidate | Adaptation |
| --- | --- | --- |
| GateRunner | Rhythm/drum interpretation, pitch and velocity modulation, phase/time transformations | Port musical semantics to the native MIDI engine with sample-accurate scheduling |
| GateRunner | Track activation masks | Later scene/pattern activation masks |
| sequence-operator | Rotation, reversal, block permutations, sequence combination and difference operations | Pure transformations, bounded output sizes, explicit combination policy and auditioning |
| NSeqArpKeys | Existing whole-preset browser and state serialization | Reuse UI conventions; introduce individual-pattern identity and versioned migration |

## Suggested next release

Ship per-pattern subdivision, copy/paste/duplicate, undo/redo, base and trigger velocity, and a basic pattern bank. Follow with ranges and rhythmic mode; introduce the broader operator/modulation system after those foundations work reliably.
