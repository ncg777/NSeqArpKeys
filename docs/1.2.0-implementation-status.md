# NSeqArpKeys 1.2.0 implementation status

Updated 2026-09-24. The [release roadmap](1.2.0-roadmap.md) now defines a bounded
1.2.0 release containing the implemented pattern features and their reliability
fixes. The five remaining feature milestones belong to future versions.

## Implemented for 1.2.0

- Per-key subdivision, including 0 for global inheritance, independent simultaneous
  rates, effective-rate display and refresh after host automation.
- Phase-preserving tempo/global/per-key rate changes, including outstanding note-offs.
  Other live assignment edits restart only the edited key with its trigger velocity.
- Melodic and rhythmic interpretation; 16 editable drum-note mappings and channel-10 default.
- Base/trigger velocity, loop-local velocity and semitone pitch lanes, transpose,
  integer rotation and reversal.
- Pattern names, independent copy/paste/duplicate and inclusive range copies with
  optional chromatic transposition. Range copies are one undo transaction.
- Bounded editor-session undo/redo, cleared on whole-preset/project restore.
- Single-pattern file save/load, sharing the same assignment serialization as DAW
  state and whole presets. Pattern load changes only the selected key and is undoable;
  the chooser works before the first local pattern has been saved.
- Atomic integer input validation (up to 4096 values); malformed text keeps the
  prior value, and the editor marks the error. Full signed integer bitmask parsing
  avoids overflow for the minimum signed integer.
- Shared-pitch MIDI ownership evaluated in event order across all active keys.
  Muted steps emit neither note-ons nor note-offs; nonzero expression stays audible.
- Preserved empty patterns and all-rest loop lengths in saved state. Legacy state
  continues to inherit global timing with compatible defaults.
- Version metadata, README, release scope, HTML manual and seven-page PDF manual.

## Verification on Windows

- Full Release builds of standalone and VST3 with JUCE 8.0.6 / Visual Studio 2022.
- All three CTest suites pass: PatternScheduler, PatternDomain and ProcessorState.
  Domain checks now remain active in Release builds (they previously used disabled assertions).
- Scheduler coverage includes additive Gate/Fixed Steps, overlap and zero-duration
  notes, simultaneous rates, shared pitches in either key order, muted/quiet expression,
  loop-local lanes, and phase/note-offs after tempo/global/per-key timing changes.
- State coverage includes all assignment fields, empty/rest patterns, legacy defaults,
  single-pattern XML round trips, independent range copies and actual processor callback
  onset/release offsets. Editing preserves trigger velocity and other sounding keys.
- Editor smoke test opens/reopens the real editor, exercises Duplicate/Undo/Redo,
  invalidates history on project restore, and undoes a range as one operation.
  Rendered editor snapshots were visually checked for clipped controls.
- Packaged `release/NSeqArpKeys-1.2.0-windows-x64.zip`; the packaging script checks the
  VST3 version, includes the PDF and SHA-256 list, and verifies ZIP integrity.
- Regenerated the manual from HTML and visually inspected all seven pages.

The CMake configuration now propagates JUCE compiler settings to plugin wrappers
and tests, including the exception settings required by the Windows compiler.

## Deferred feature milestones

The future roadmap retains the searchable/tagged/favourite pattern bank and shared
pattern identity; shared ranges, channel filters and set-degree expression; advanced
rhythm, velocity bits, swing and microtiming; non-destructive operator chains and
independent modulation clocks; and scenes, follow actions, seeded mutation and MIDI
capture/export. These are no longer unfinished 1.2.0 requirements.
