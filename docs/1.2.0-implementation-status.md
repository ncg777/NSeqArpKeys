# NSeqArpKeys 1.2.0 implementation status

Updated 2026-09-30. The implementation and Windows/release verification sections
below preserve the historical 1.2.0 snapshot recorded on September 24. Subsequent
delivery and current host coverage are summarized separately. See the
[release roadmap](1.2.0-roadmap.md) for the original full scope and status through
[1.4.2](https://github.com/ncg777/NSeqArpKeys/releases/tag/v1.4.2), published
September 30, 2026 (UTC). The smaller 1.2.0 release did not complete that full scope.

## Implemented for 1.2.0

- Per-key subdivision, including 0 for global inheritance, independent simultaneous
  rates, effective-rate display and refresh after host automation.
- Phase-preserving tempo/global/per-key rate changes, including outstanding note-offs.
  Other live assignment edits restart only the edited key with its trigger velocity.
- Melodic and rhythmic interpretation; 16 editable drum-note mappings. Mode changes
  preserve the selected MIDI output channel.
- Base/trigger velocity, loop-local velocity and semitone pitch lanes, transpose,
  integer rotation and reversal.
- Pattern names, independent copy/paste/duplicate and inclusive range copies with
  optional chromatic transposition. Range copies are one undo transaction.
- Bounded editor-session undo/redo, cleared on whole-preset/project restore.
- Single-pattern file save/load, sharing the same assignment serialization as DAW
  state and whole presets. Pattern load changes only the selected key and is undoable;
  the chooser works before the first local pattern has been saved.
- Atomic integer input validation (up to 4096 values); malformed text keeps the
  prior value, and the editor marks the error. Full signed integer bitmask parsing
  avoids overflow for the minimum signed integer.
- Shared-pitch MIDI ownership evaluated in event order across all active keys.
  Muted steps emit neither note-ons nor note-offs; nonzero expression stays audible.
- Preserved empty patterns and all-rest loop lengths in saved state. Legacy state
  continues to inherit global timing with compatible defaults.
- Version metadata, README, release scope, HTML manual and seven-page PDF manual.

## Verification on Windows (historical 1.2.0 results)

- Full Release builds of VST3 with JUCE 8.0.6 / Visual Studio 2022.
- All three CTest suites pass: PatternScheduler, PatternDomain and ProcessorState.
  Domain checks now remain active in Release builds (they previously used disabled assertions).
- Scheduler coverage includes additive Gate/Fixed Steps, overlap and zero-duration
  notes, simultaneous rates, shared pitches in either key order, muted/quiet expression,
  loop-local lanes, and phase/note-offs after tempo/global/per-key timing changes.
- State coverage includes all assignment fields, empty/rest patterns, legacy defaults,
  single-pattern XML round trips, independent range copies and actual processor callback
  onset/release offsets. Editing preserves trigger velocity and other sounding keys.
- Editor smoke test opens/reopens the real editor, exercises Duplicate/Undo/Redo,
  invalidates history on project restore, and undoes a range as one operation.
  Rendered editor snapshots were visually checked for clipped controls.
- Preview sound can be disabled independently for MIDI-only use. Its saved state
  defaults to enabled for old projects. Playback tests verify silent audio while
  notes continue, and sound returning when re-enabled during a held pattern.
- Packaged `release/NSeqArpKeys-1.2.0-windows-x64.zip`; the packaging script checks the
  VST3 version, includes the PDF and SHA-256 list, and verifies ZIP integrity.
- Regenerated the manual from HTML and visually inspected all seven pages.

The CMake configuration now propagates JUCE compiler settings to plugin wrappers
and tests, including the exception settings required by the Windows compiler.

## Subsequent delivery through 1.4.2

- [1.3.0](release-notes-1.3.0.md) shipped the searchable/tagged/favourite Pattern
  Bank, shared linked identities, embedded definitions, selective editing,
  previews and independently active linked keys. Linked timing edits preserve phase.
- 1.3.0 also shipped 1-16 drum pitches with one shared 1-7-bit velocity width per
  lane, up to 112-bit positive masks, and binary-mask compatibility. The 1.2.0
  pitch/velocity step lanes were removed; old lane values are ignored on restore.
- [1.3.1](release-notes-1.3.1.md) added whole-bank `.nseqbank` import/export.
- [1.4.0](release-notes-1.4.0.md) added melodic Forte-set-degree Transpose and
  Transpose by key, plus built-in Factory Patterns banks. Rhythmic transpose stays
  chromatic. Saved nonzero melodic transpose numbers can sound different from 1.3.1.
- [1.4.1](release-notes-1.4.1.md) shipped the compact, resizable editor.
- [1.4.2](release-notes-1.4.2.md) added balanced MIDI retriggers, shared-pitch
  release handling and transport/panic/lifecycle cleanup, with a fourth test target
  for MIDI lifecycle regressions. This is separate from host integration testing.

Per-key rates and phase-preserving tempo/global/per-key rate changes already
shipped in 1.2.0; they are not deferred features. Linked bank identities are not a
live range model: Assign range still creates independent key assignments.

## Remaining original roadmap scope

Commit
[`cafead7`](https://github.com/ncg777/NSeqArpKeys/commit/cafead74ae00be593e444c7f06160ed9b59aaac4)
explicitly deferred the broader milestones when staging 1.2.0. This is a record
of what was deferred, not acceptance of a reduced original roadmap. Features
subsequently delivered above must no longer be listed as future work.

- Distinct live ranges with root/channel filters, range-position parameter mappings,
  overlap priority/layering, velocity sensitivity/curves and pitch-offset lanes.
- Independent accents/drum gates, probability, ratchets, swing, microtiming/time warp
  and density-preserving seeded mutation. Euclidean generation was explicitly
  [removed before 1.2.0 shipped](https://github.com/ncg777/NSeqArpKeys/commit/6c3d7c6f568ba2dec64ee463489c2ca8f0ff6033)
  and remains unshipped.
- Advanced pattern operators, non-destructive chains, unequal-length policies,
  independent modulation clocks, MIDI CC/expression mappings and macros.
- Quantized launch/switching, one-shot/per-assignment latch, exclusive groups,
  scenes/follow actions, mutation capture and performed MIDI capture/export.

The historical loop-local lanes are not current features, and the existing
hold/global-latch controls do not deliver the advanced performance milestone.
